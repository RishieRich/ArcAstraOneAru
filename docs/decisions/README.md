# Architecture decision records

Create an ADR when a change makes a durable choice that future work should not casually
reverse: authentication model, data ownership, deployment topology, migration strategy,
external provider boundary, or a major dependency.

Do not create an ADR for ordinary implementation detail.

Statuses are `Proposed`, `Accepted`, `Superseded`, or `Rejected`. Once accepted, preserve the
record. A later decision supersedes it with a new ADR.
